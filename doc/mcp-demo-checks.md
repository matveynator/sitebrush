# Проверка MCP после обновления сервера

Изменения начинают действовать после установки версии из PR. Проверки ниже
можно выполнить вручную; автоматические локальные проверки используют настоящий
MCP SDK, Chromium и штатный маршрутизатор БД, но не заменяют подключение Claude.

1. Откройте `https://demo.sitebrush.com/?mcp` в приватном окне. Должны появиться
   инструкции без входа и циклических перенаправлений. Откройте также главную
   демо без сохранения cookie: она должна ответить без цикла редиректов.
2. В Claude Code добавьте сервер:

   ```sh
   claude mcp add --transport http sitebrush-demo 'https://demo.sitebrush.com/?mcp'
   ```

   Затем откройте `/mcp` и включите инструменты SiteBrush. Для демо вход и
   отдельное подтверждение доступа не нужны. В веб-версии Claude добавьте этот
   же адрес как Custom Connector и включите его в разговоре.
3. Попросите: «Проверь доступ и руководство SiteBrush, изучи страницы демо.
   Заморозь публикацию, измени заголовок главной и повторяющийся блок на связанных
   страницах. Покажи результат перед публикацией». В другом приватном окне
   опубликованный сайт должен сохранять прежнее содержимое.
4. Попросите опубликовать результат. Изменения должны появиться на всех
   затронутых страницах. Затем попросите откатить выбранную страницу к прежней
   ревизии вместе с общими блоками и опубликовать. При отключении последней
   активной ревизии помощник должен сообщить о постановке всей страницы на
   удаление; её можно восстановить включением ревизии до публикации.
5. Попросите загрузить картинку и PDF, вставить возвращённые `/p/` ссылки в
   страницу. Для отдельного раздела задайте пароль и привяжите к нему выбранный
   файл через MCP или «Файлы → Доступ → Пароль раздела». Прямой URL файла в
   новом приватном окне должен требовать разблокировать раздел. После ввода
   пароля раздела файл открывается. Удаление правила пароля само по себе не
   делает привязанный файл публичным: измените доступ явно.
6. Попросите отчёты посещаемости и безопасности за 7 дней. Ответ должен
   учитывать отсутствие/неполноту наблюдений и не содержать IP, сырых журналов,
   значений форм или паролей.
7. Проверьте обычный сайт: подключение с разрешённого IP/сети требует OAuth
   владельца. Отказ и отзыв доступа блокируют дальнейшие операции. Демо не
   должно давать доступ к обычному сайту или похожему домену `demo.*`.

Демо общее для всех и автоматически сбрасывается. Не используйте реальные
персональные данные или пароли от других сервисов. Отправка ссылки в обычный
чат сама по себе не устанавливает MCP-сервер: подключите его в настройках клиента.
