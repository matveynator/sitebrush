# SiteBrush Billing: владельцы серверов, клиенты и платежи

## Принципы

SiteBrush — единая биллинговая платформа для независимых владельцев серверов. Клиент оплачивает услуги в интерфейсе SiteBrush, а не вручную по ссылкам, созданным отдельным администратором. SiteBrush получает оговорённую комиссию за подтверждённую транзакцию. Стоимость хостинга, индивидуальные услуги и комиссия платформы должны быть объяснимыми для клиента до оплаты.

**Нет общей изменяемой копии состояния между серверами.** Головной платёжный сервер — единственный владелец истинного журнала событий Stripe; каждый сервер владеет своей локальной проекцией своих клиентов и счетов. NetChan переносит событие и право подтвердить его применение, а не «общий баланс».

**Нельзя считать webhook и NetChan равнозначными.** Внешний Stripe вызывает HTTPS webhook головного сервера; NetChan используется только между доверенными установками. Подпись Stripe, уникальность event ID и состояние PaymentIntent проверяются в центре. Получатель через NetChan сверяет installation ID и номер/валюту/сумму счёта с собственной БД. Перемещение денег происходит в Stripe, а не по NetChan.

## Роли и данные

- **Платформа SiteBrush:** Stripe Connect platform account, центральный журнал `payment_events`, комиссии, расход Stripe, выплаты, возвраты, chargeback, аудит, разрешённые модели продавца.
- **Владелец сервера:** свой connected account (без необходимости создавать Stripe API ключи), payout status, полученные средства, сумма комиссии, выставленные клиентам счета, индивидуальные услуги.
- **Клиент:** сайты, текущие и архивные счета, безопасная страница оплаты, квитанция, история платежей.
- **Счёт:** неизменяемый снимок продавца, покупателя, юридических реквизитов, валюты, срока, строк с количеством/единицей/ценой/налогами, тарифа и версии расчёта; редактировать можно только черновик, исправления выданного счёта — кредит-нота/сторно.
- **Персональная услуга:** отдельный идентификатор, установка, клиент, опциональный сайт, описание, единица, цена в minor units, валюта, периодичность, дата начала и окончания, статус. Не заменяет оплату хостинга.

Данные одного installation ID никогда не попадают в журнал другого. На головном сервере доступен агрегат с явным указанием валют и установленными правилами доступа.

## Расчёт и будущие счета

Для тарифа на основе месячных затрат:

```
billing_capacity = full_server_disk_capacity * billing_percent / 100
monthly_storage_price_per_GB = monthly_server_cost / billing_capacity_GB
client_storage = sum(allocated site storage charges)
client_services = sum(active scheduled extra services)
future_monthly_invoice = client_storage + client_services + applicable taxes/fees
```

Процент по умолчанию — 30%. Делитель — **вся физическая ёмкость диска сервера**, а не занятое место. Распределение затрат на платные сайты детерминировано с округлением в минимальных денежных единицах. Ручные договорные тарифы, скидки и исключения имеют явный приоритет перед автоматическим хранением. Дополнительные услуги не распределяются между чужими сайтами.

Каждое изменение тарифа создаёт новую версию с моментом вступления в силу. Будущая сумма **пересчитывается при построении прогноза и при формировании ещё не выставленного счёта**; периодическая услуга включается в соответствующий календарный интервал. Не пересчитывать статусы, суммы и строки уже выставленных счетов, архивные периоды и оплаченные счета. Старые неоплаченные *выставленные* счета тоже неизменны; для корректировки нужен отдельный документ. После подтверждения сохранения показать разницу по клиентам, валюта/период и дату нового тарифа.

## Stripe Connect / коммерческая модель

Предлагаемая начальная модель — Stripe Connect + Checkout с destination charge и `application_fee_amount`. Платформа должна быть зарегистрирована в поддерживаемой юрисдикции и успешно пройти Stripe onboarding. Возвраты, выплаты и обязательства merchant of record/налогов зависят от юридической модели и соглашений; **до запуска реальных платежей её нужно утвердить**, отдельно от кода.

Платформа хранит только идентификаторы Stripe (acct_, cs_, pi_, evt_), ссылки на зарегистрированные объекты и результаты операции. API secret, webhook secret и платёжные реквизиты не записываются в HTML, URL, NetChan-сообщения, логи или клиентские хранилища. Stripe Checkout Session создаётся сервером из неизменяемого счёта; application fee определяется платформой, а не пользователем из формы. Success URL никогда не переводит счёт в `paid`.

Разделять в отчётах `amount collected`, Stripe processing fee, SiteBrush application fee, amount due to server owner, actual payout, refunded and disputed amounts. Не складывать USD с EUR. Прогнозные доходы не являются полученными платежами. Для валидной сверки нужны реальные `balance_transaction` и payout events из Stripe, не расчётная оценка из комиссии.

## Передача платежа по NetChan

```text
Stripe signed webhook (HTTPS)
      ↓
Platform billing owner:
  verify signature + payment status
  validate invoice, tenant, amount, currency
  INSERT payment_event once + update journal (single SQL transaction)
      ↓
Outbox: pending delivery for installation ID
      ↓
NetChan v2 authenticated session / typed Message
      ↓
Remote server billing owner:
  authenticate central identity
  match installation ID, invoice, currency, amount
  INSERT event ID once + apply local projection atomically
      ↓
one-shot reply channel: committed / duplicate / rejected
      ↓
Platform outbox marks delivery only after committed ACK
```

После таймаута неизвестно, завершилась ли удалённая фиксация. Повторно отправлять **тот же event ID**; сервер принимает повтор без повторной оплаты. Срок ожидания, overflow queue, peer disconnect, restart и cancellation не могут превращать неопределённость в `paid`. Ошибки журнала возвращаются без утечки секретов. Реальный обработчик обязан использовать один владеющий БД actor либо согласованный single-writer SQL boundary. Владелец NetChan endpoint закрывает сессию после остановки активного worker.

## UI: сервер → Клиенты и сайты / Счета и платежи / Монетизация

1. **Клиенты и сайты:** быстрое имя/email/домен, число сайтов, объём, цена, платёжный статус, краткая сводка. Раскрытие показывает сайты и квоты. Удаление и управление администраторами — только контекстные действия с подтверждением; счета ведут на фильтрованную страницу биллинга.
2. **Счета и платежи:** вверху четыре показателя (прогноз, получено, ожидает, просрочено) с периодом и валютой; ниже единая история с поиском/статусом/периодом, новый счёт, просмотр документа. Для неготового Stripe показывать «не подключено», не утверждать автоматическую оплату.
3. **Монетизация:** тариф сервера, 30% диска по умолчанию, дата вступления, предварительный перерасчёт по клиентам и подтверждение. Вычисления только на backend, JavaScript — подсказка.
4. **Карточка клиента:** сайты, тариф, индивидуальные платные услуги (разовая работа, консалтинг, дизайн, поддержка), частота, дата начала/окончания, прогноз следующего счёта, все счета, платежи и возвраты.
5. **Профиль счёта:** загружаемый логотип, официальное название поставщика, юридический/почтовый адрес, регистрационный и налоговый идентификатор, адрес покупателя, дата, номер, описание услуг, период, единицы, налоги, итог, сроки и способ оплаты. По умолчанию — нейтральная композиция с логотипом SiteBrush; реквизиты не придумывать.
6. **Документ:** спокойная обложка, таблица работ, цена/скидка/налоги, понятная итоговая сумма, кнопка оплаты и печать A4. В момент выставления сохранять неизменяемый снимок профиля и шаблона.

### Что уже реализовано в PR #282

Новая навигация, поиск, панель истории, ручное выставление счетов существующим backend, оформление клиентского счёта, 16 переводов; пакеты `billingworkspace`, `stripeconnect`, `billingnetchan` и их модульные тесты.

### Что ещё не реализовано (не считать завершённым)

Персистентные индивидуальные услуги и их UI, настройка профиля счёта с адресом и логотипом, настоящие Stripe Connect onboarding/session/webhook/balance reconciliation, durable outbox и transport binding в рабочем сервере, автоматическая публикация будущих счетов из versioned tariff+extras, настоящая сводка всех доходов и выплат из Stripe, расширенные сценарии возврата/спора, тесты endpoint-авторизации и реального исполнения в браузере. До выполнения этих пунктов Stripe не должен быть включён как производственный провайдер.

## Регрессии перед включением в production

- Тариф: старый/новый, 30% по умолчанию, разные размеры диска, нулевой, превышение лимита, микросуммы, округление, валюта и специальные цены.
- Счета: повторный выпуск за период не создаёт второй счёт; закрытые периоды и выставленные суммы не меняются; персональные услуги не попадают к другим клиентам и серверам.
- Stripe: успешный платёж/неудача/частичный/повтор webhook/ошибка подписи/задержка/состояния asynchronous; settlement, payout, возврат, chargeback, комиссия и валюты.
- NetChan: неверный центральный сертификат, неверная установка, повтор ID, отказ SQL, таймаут после commit, реконнект, старый и новый протокол, заморозка/остановка worker, полнота idempotency.
- UI: обычный/головной/удалённый сервер, несколько установок, пустые счета, длинные имена/адреса, фильтры, мобильный экран, печать и локализации.
