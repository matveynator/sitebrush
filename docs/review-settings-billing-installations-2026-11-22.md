## UI/ergonomics conclusions

- **Website settings:** the top-level sections Overview → Domains → Search → Backup → Folders establish a useful progression. DNS steps and technical records stay in disclosures. Destructive controls should require explicit disclosure or confirmation; ordinary actions should remain immediate.
- **Server settings:** a single local workspace with Overview, Network, Updates, Clients, Billing, Registration, Demo and Monetization. The navigation is context-sensitive and avoids repeating server-wide public IPs on every site.
- **Temporary sites:** a separate root-level workspace, visible to server owners rather than a subtype of an installation. Archive and sensitive diagnostics should be secondary.
- **Installations:** a unified catalogue for server, desktop and archived instances by stable `InstallationID`, visible only when `ShowCentralRegistry` is authorized for the SiteBrush.com origin; sort by site count, forecast, paid amount or name, filter monetization state. Global money should remain currency-scoped.
- **Billing:** keep one timeline of invoice documents, separate forecast from real receipts, ensure a single primary action “Issue invoice”, and use the same versioned server policy in preview and generation. The current template uses a branded print layout but still needs merchant and buyer addresses, verified legal identities, taxes, and issuer-defined logos before live use.

## Ownership/security and verification

- No new mutexes or application atomics have been added by this PR. The write to `server_expense_policies` remains inside the existing database owner callback, and a disabled mode update is one read-validate-insert operation at that boundary.
- New handling of opt-out passes a scalar immutable `monetization_mode` from HTTP and never changes historical invoice rows. The new alias UX does not replace server-side CSRF/authorization, and its second step works with JavaScript off.
- Existing `.codex/AGENTS.md` exceptions are unchanged: `publicHTTPInFlight`, `PublicRuntime.current` and `publicGeneration.readers`. No change to the static serving path.
- Added regression tests for preserving price/percentage/currency when disabling billing with invalid or absent tariff fields, rejecting invalid modes, and requiring disclosure before an alias deletion form.
- Run Security, Ownership, race, native and cross-build checks on the new PR. Success is not assumed until the jobs finish. Performance targets and OpenBSD runtime behavior require separate user-side measurements.
