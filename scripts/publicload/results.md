# Контрольные замеры публичного ingress

Linux/arm64 в локальном Docker на Apple M1, Go 1.27.3, `CGO_ENABLED=0`, 4 CPU. Сравнение с `61cd656` плюс та же диагностика и тот же нагрузочный стенд. Для каждой строки — медиана пяти прогонов по 10 000 запросов после отдельного прогрева. Ответ: 8836 байт, проверены статус, длина и SHA256.

Обе версии: 600 000 из 600 000 проверенных ответов успешны; транспортных ошибок и несовпадений содержимого нет. Эти цифры характеризуют данный локальный стенд.

## Стоимость и ограничения

- Серверный benchmark без сетевого генератора: медиана 15 170 → 12 934 нс/запрос. Allocations: **121 → 124**, объём **21 257 → 22 074 байт/запрос**. Рост allocations остаётся открытым ограничением; цель снижения выделений полностью не достигнута.
- Ёмкость каждого security shard увеличена с 256 до ограниченных 2048 задач. Пороговые правила не изменены. Это увеличивает постоянный расход памяти очередей и позволяет принять предусмотренный burst без обхода проверки.
- Дополнительная матрица: 135 прогонов по 1000 запросов — разные IP, один shard, полная очередь аналитики, отсутствующий consumer, block/throttle, burst, отключённая диагностика, HTTP/2, TLS 1.2 и resumption. Все сценарии завершились с ожидаемыми результатами; 429 в сценариях ограничений учитываются отдельно от полезного RPS.
- Полный набор тестов не объявлен зелёным: PHP-assertion на старое меню и зависание cleanup demo-теста воспроизведены также на контрольной версии. Расширенный публичный/TLS/security набор и затронутые пакеты прошли. Контрольный server cross-build прошёл для macOS/Linux/Windows/FreeBSD/OpenBSD, amd64/arm64. Последние изменения ёмкости очередей и счётчиков включены в итоговые Linux-замеры; повторный cross-build после них оставлен пользователю.
- После запроса пользователя передать дальнейшие проверки ему новые тесты не запускались. Результаты CI для PR здесь не заявляются.
